Security & contact

Status: not yet formally audited. Tidify is an early protocol. Funds remain in your wallet at all times and every transaction is user-approved, but use it with appropriate caution.

Design posture

  • Non-custodial. User funds never enter a Tidify-controlled account; the protocol vault only ever receives the protocol fee.
  • User approval. Every account that gets touched is explicitly selected and signed by the user. Nothing is forced or batched without approval.
  • On-chain fee caps. Fee rates and ceilings live in the config account; the swap path enforces the user's fee ceiling on the realized amount.
  • Read-only previews. The guest preview performs no writes at all.
  • Unverified tokens. Positions without verifiable metadata are labeled "Unverified token" with an explorer link — never silently swapped.

Responsible disclosure

Found a vulnerability in the Tidify program, the web app, or the docs? Please report it privately before disclosing publicly:

Email: security@tidify.xyz

Please include:

  • Description of the issue and its impact
  • Steps to reproduce or a proof of concept
  • Affected component (program / web app / docs)
  • Suggested fix, if you have one

We aim to acknowledge reports within 3 business days and to keep you informed as the issue is triaged. If you prefer to stay anonymous, use a throwaway email address.

General contact

Questions, feedback, or feature ideas: help@tidify.xyz. For anything security-related, use security@tidify.xyz.
